# MCP audio verification, 6 November 2026

## Environment

The receive-only listener ran inside the existing KVM container on bsociety, against its configured real PiKVM. The probe used the container's existing target credentials without printing them. No target audio was saved.

## Real MCP tool

The bundled `scripts/audio-smoke.ts` ran inside that container:

```sh
yarn exec tsx scripts/audio-smoke.ts
```

For the container run, esbuild bundled the script, with OpusScript and sharp provided externally. Node ran the bundle with the container's existing environment. The real MCP handler called the real Desk and negotiated Janus audio.

| Check | Result |
| --- | --- |
| Tool | `listen` |
| MIME type | `audio/wav` |
| Duration | 1000 ms |
| WAV size | 192044 bytes |
| Format | Stereo, 48000 Hz, 16-bit PCM |

The smoke command validated the RIFF header, data size, channels and sample rate. It disposed the Desk after the call.

## Concurrent browser audio and microphone

A headless Chromium connection used the same Janus watch/start protocol as the app. Its audio transceiver received target audio and sent a synthetic silent microphone track. Two independent server listeners then each recorded one second and destroyed their own sessions.

The temporary test bridge used the application's existing target credentials and self-signed-certificate policy. Its WebSocket path was restricted to the test. The bridge process was stopped after the check. It was not added to the app or deployed configuration.

| Browser measurement | Before recording | After recording |
| --- | --- | --- |
| Connection | Connected | Connected |
| Microphone track | Live | Live |
| Received audio packets | 10 | 125 |
| Sent audio packets | 9 | 320 |
| Protocol errors | 0 | 0 |

Both server listeners returned 192044-byte WAV files. Local machine evidence is saved at `~/.cache/pk-e2e/audio/concurrency.json`. The browser test command was `node ~/.cache/pk-e2e/audio/browser-check.mjs`.

## Limits

This proves concurrent Janus audio reception and microphone transmission through Chromium. It does not verify a physical microphone, the packaged desktop app, mobile browsers, or model support for audio blocks. Executor approval rules were not changed.
